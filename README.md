# 公司轻量知识库

把业务开发中弄懂的知识持续积累下来，把容易散落在聊天记录里的信息保存为可检索的备忘。主要由一人维护，同事通过各自的 AI Agent 共同使用。

本仓库由 **Git、Markdown 和仓内 Agent 规则**组成。首版只包含业务知识与信息收件箱；运行结构检查需要 Python 3.10 或更新版本。初始仓库没有真实业务记录，演示内容均为虚构。

## 从这里开始

| 需要做什么 | 入口 |
|---|---|
| 首次接入自己的 Agent | [接入说明](docs/setup.md)、[启动提示词](prompts/bootstrap.md) |
| 用自然语言提出问题 | 让 Agent 按 [问题入口](questions.md) 和 [全库导航](index.md) 查找 |
| 按体系回顾知识 | [业务知识体系](knowledge/index.md) |

| 了解记录与查询怎么执行 | [操作流程](docs/workflows.md)、[虚构示例](docs/examples.md) |
| 修改知识库机制 | [设计文档](DESIGN.md)、[维护记录](CHANGELOG.md) |

对 Agent 的执行规则以 [AGENTS.md](AGENTS.md) 为准；知识与备忘的局部规范分别在 [knowledge/README.md](knowledge/README.md) 和 [inbox/README.md](inbox/README.md)。

## 日常只需这样表达

- “把这次讨论整理成知识，记入知识库。”
- “记一下：示例分支构建前要带上指定修复提交。”
- “之前那个特性的设计文档在哪里？”
- “结合当前分支，核查这条构建备忘现在是否还适用。”

普通问答留在对话中。AI 可以建议记录，**写入和整理必须由用户发起**。用户授权一次任务后，Agent 在范围内完成必要的正文、挂载、索引与维护记录；无需让用户逐个填写字段或逐个批准文件。

## 内容如何积累

| 内容 | 组织方式 | 更新方式 |
|---|---|---|
| 业务知识 | 业务领域 → 主题 → 知识点；一份正文，多个问题入口 | 先检索，再增量整合已有主题，保留依据与历史条件 |
| 信息备忘 | 按记录月份保存；标题、别名、分支、特性等线索辅助查找 | 保留原话、来源和适用范围；整理或转为知识由用户另行发起 |

问题入口帮助“找回来”，知识体系帮助“理解和记住”。索引只放导航信息，正文只维护一份。

查询涉及会变化的实现或业务约定时，Agent 结合可访问的当前代码、分支和来源只读核查；回答区分历史记录、当前证据和未知项。查询中的发现不会自动写回知识库。

## 共享和部署

每人克隆同一个共享仓库，通过自己的 Agent 使用。仓内规则需要按 [接入说明](docs/setup.md) 显式加载；个人的业务代码路径放在被 Git 忽略的 `workspace.local.md`。来源引用使用仓库标识、版本和文件／符号，便于不同电脑上的同事复核。

这个 GitHub 仓库初始化时为公开仓库，交付内容是通用框架。存放真实公司信息时，使用公司允许的仓库及访问范围；部署前按实际 remote 配置共享位置。

## 检查

```bash
python3 scripts/check_knowledge.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
git diff --check
```

检查器只验证链接、元数据及索引覆盖等结构问题，不验证技术事实或 Agent 是否真正遵守规则。详见 [工具说明](scripts/README.md) 和 [验收说明](tests/README.md)。
