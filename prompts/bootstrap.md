# 在自己的 Agent 中接入知识库

把下方提示中的本地路径替换为实际值后，发给自己的 Agent。每个新会话需要确认 Agent 已读规则；不要假设在业务代码仓启动会自动加载知识库的 `AGENTS.md`。

```text
我们使用一个独立的共享知识库。
知识库本地路径：<KB_ROOT>
本次需要分析的业务代码仓路径：<CODE_ROOT；没有则写未配置>
本次目标分支/版本：<明确目标；尚未确定则写待确认>

先读取知识库的 README.md、AGENTS.md、index.md，按任务再读局部规范和 docs/workflows.md。
如存在 workspace.local.md，读取其中的本地仓库映射；它只用于本机定位。

现在先确认你已理解：普通问答和只读核查不改库；你可以提醒沉淀价值，
但只有我明确要求记录、更新或整理时才执行写入。不要因接入而创建知识或备忘。

我提问时，按规则检索已有知识和备忘；涉及当前实现时，结合明确的业务代码仓与版本只读核查。
我要求记录时，在授权范围内完成正文、合理挂载、相关索引和必要检查。
遇到来源缺失、版本不明或证据冲突时说明事实，不把历史记录当成当前结论。
```

一次会话内的具体记录请求，例如“把刚才的分析整理入库”，才是本次写入依据。上面的接入提示本身是读取和使用规则的指示。
