# 使用示例

以下内容全部是虚构场景与占位标识，用来说明操作行为，不代表真实公司分支、提交或训练实现。示例不进入生产知识索引，不构成已验证技术结论。

## 1. 从讨论沉淀知识

用户说：“把刚才关于训练恢复的讨论整理入库。”

Agent 在本次授权范围内：

1. 查知识体系、问题入口及同义词，确认是否已有相同主题。
2. 从当前对话和实际读取的来源整理结论，区分通用原理、公司实现和待确认项。没有实际证据时不声称某状态一定恢复或一定丢失。
3. 更新已有主题，或新建 `knowledge/训练基础设施/训练恢复.md`；正文只维护一份。
4. 在知识体系中挂载“训练基础设施 → 状态管理 → 训练恢复”，在问题入口关联“恢复后与连续训练有什么差异”等实际问题。
5. 进行结构检查并检查来源支撑，按共享流程交付。

预期回报示意：

> 已整理训练恢复主题，并关联本次问题。公司实现部分依据本次实际读取的版本；尚未覆盖的运行验证已列为待确认。知识体系和问题入口已同步。

普通提问“恢复后会不会有差异？”只触发检索与回答。Agent 可以提醒记录价值，不能执行上述写入步骤。

## 2. 捕获一条构建备忘

用户说：“记一下，示例分支 demo/release-a 构建时需要带示例修复 FIX-DEMO；设计文档地址稍后补。”

Agent 保留原话，创建备忘并更新备忘索引；不猜测提交 SHA、设计文档地址或要求仍有效的截止日期。元数据示意：

```yaml
id: M-20261109-demo-build-fix
title: 示例分支的构建修复要求
recorded: 2026-11-09
scope: 示例仓库待确认；demo/release-a
status: recorded
```

正文将来源记为用户提供，消息发生日期若未明确则写待确认。检索摘要可提取“demo/release-a、构建、FIX-DEMO”，但不能把这些线索当成核查结果。

## 3. 查找记录并核查当前情况

用户问：“示例分支 demo/release-a 现在怎么构建？”

Agent 先找回备忘，再检查本次明确指定的代码仓与版本。回答应分开说明：

| 部分 | 应返回的信息 |
|---|---|
| 历史记录 | 何时记录过什么要求、原始来源和当时范围 |
| 当前核查 | 本次实际检查的 repo、分支／commit、是否包含工作区改动，以及证据支持什么 |
| 当前建议 | 有依据的操作结论及仍未确定的部分 |

若核查表明要求已变化，在当前回答中说明变化及依据。没有收到“更新记录”的指示时，不改备忘正文、状态、索引或维护记录。

## 4. 无法核查或信息冲突

代码仓未配置时，合适的回答是：“找到一条日期为某日的构建要求，适用于记录中的示例分支。当前无法访问对应代码仓，尚未确认要求是否仍适用；请提供该仓路径或目标版本以便核查。”

存在两条矛盾消息时，列出各自日期、来源和适用范围。较新的记录不必然适用于当前分支；不能仅按时间覆盖结论。查询中发现冲突可提示维护需求，修改仍需用户发起。

## 5. 用户发起维护

用户说：“把刚才核查到的变化更新到这条备忘。”

Agent 才可在该条及必要关联范围内写回，保留旧要求与历史来源，说明新依据。若事项已有明确后续记录，可标记替代关系；未经授权，不顺带清理其他收件箱条目。
