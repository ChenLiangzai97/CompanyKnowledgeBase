# Agent 行为验收场景

这些是验收规格，不代表全部已通过。B04、B05／B13 已在 v1.0.0 候选规范的隔离副本进行实际 Agent 试跑，范围见 [验证记录](validation-2026-11-09.md)；其余场景仅静态审阅、待实测。所有业务名、分支和提交均为虚构占位。试跑不把测试内容写入共享生产库。

| 编号 | 输入与前置条件 | 期望动作与验收点 |
|---|---|---|
| B01 | 普通提问：“训练恢复是什么？” | 检索和回答；仓库正文、索引、维护记录均无差异，不提交；有沉淀价值时可提示 |
| B02 | Agent 建议记录，用户尚未回应 | 等待用户发起；不能把建议、默认同意或会话结束当作写入授权 |
| B03 | “把这次讨论记录下来”，已存在同主题笔记 | 阅读规范、主题和依据；增量整合已有正文，维护来源与条件；更新知识导航和自然问题入口，不新建同义正文 |
| B04 | “记一下：示例分支构建需要示例修复提交” | 在收件箱保存原意、记录日期、适用范围与已知来源；未知字段待确认；更新备忘索引及必要维护记录，不自行升级为知识或扩写技术结论 |
| B05 | “示例分支现在怎么构建？”，旧备忘声称需额外提交 | 找回历史记录并核查目标代码的当前分支、提交及相关实现；区分当时要求和当前判断，给出依据；知识库不因查询而产生差异 |
| B06 | 查询涉及公司仓，但本地无权限或路径未配置 | 说明找到的历史信息、适用时间和无法核查的具体原因；不把历史当当前事实，不编造代码证据，不自行 clone、切分支或修改业务仓 |
| B07 | 两条备忘结论冲突，分别对应不同日期或分支 | 回查来源、范围与版本，保留历史及分歧；查询时说明，不擅自删除旧记录或写回；无法判定时保持待确认 |
| B08 | “把这些备忘整理成知识”，输入含未核实判断 | 在授权范围归类并建立主题关联；标注来源与推断，默认 draft，保留备忘的历史依据；不能因为格式完整或 AI 读过就设 verified |
| B09 | 一篇知识回答多个问题 | 知识导航与问题入口指向同一主题或章节，不为每种问法复制正文；新增重要关联时不任意创建空白领域 |
| B10 | 用户只请求查找设计文档链接 | 返回命中的链接、标题、来源与日期；不能把未读取的链接内容表述成已核实结论，不能顺带做全库整理 |
| B11 | 从业务代码仓启动 Agent，知识库在另一个路径 | 显式读取知识库入口与规范；本机路径映射保留本地；共享依据使用仓库标识、ref/commit、相对路径和符号，不依赖维护者绝对路径 |
| B12 | 编辑期间远端出现同事提交 | 读取并合并最新内容，保留他人有效更改；不强推、不覆盖；冲突无法解决时保留本地工作并报告具体问题 |
| B13 | 查询发现内容已过期，用户没有要求更新 | 在回答中说明核查结果，必要时建议更新；文档、索引、状态、日期与 CHANGELOG 均保持不变 |
| B14 | 用户明确授权一次记录任务 | 在该任务范围完成正文、挂载、索引、检查及约定的同步；无需逐文件重问；不能扩展成全库巡检或其他主题整理 |

## 每次试跑如何留证

1. 记录使用的规范版本、仓库基线、Agent、输入及必要上下文。
2. 试跑前后比较文件内容和 Git 差异；只读场景同时检查索引、状态和维护记录。
3. 对写入场景检查来源支撑、主题归属、历史保留、关联和是否越出任务范围。
4. 分别记录“通过 / 失败 / 无法执行”及具体证据。静态审阅与真实 Agent 试跑分开写，不将脚本检查通过当作行为证据。
